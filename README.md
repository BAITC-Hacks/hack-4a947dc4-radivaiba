# Career Quest

AI-навигатор развития сотрудника для HackAlem AI: профиль, карьерная траектория, объяснимые рекомендации, обновление навыков и HR-обзор. React + TypeScript + Vite, Go, PostgreSQL 18, OpenAI-совместимый API.

## Быстрый запуск

Установите **Node.js 24**, **Go 1.25+** и **Docker Desktop**. Стартовый набор организаторов не хранится в Git. Из корня репозитория:

```powershell
npm run setup -- --data-dir "C:\Users\ВАШЕ_ИМЯ\Downloads"
docker compose up -d --wait postgres
npm run credentials
npm run demo
```

Откройте **http://localhost:8080**. Выберите «Сотрудник» или «HR-команда», введите соответствующий пароль из `npm run credentials`. Сотрудник по умолчанию — `E0001`; HR открывает любой профиль, включая профиль жюри.

`setup` принимает `skills.json`, `employees.json`, `events.json`, `activity_history.csv` и варианты `skills(1).json` и т. п. Он копирует файлы в `data/seed`, проверяет набор без подключения к БД, создаёт `.env` со случайными демо-паролями и паролем PostgreSQL, затем устанавливает зависимости по lock-файлу. Повторный setup сохраняет настроенные значения `.env` и добавляет отсутствующие параметры БД.

После подготовки и запуска PostgreSQL приложение запускается командой **`npm run demo`**. Первый setup требует доступа к npm и Go proxy. `Ctrl+C` останавливает приложение, PostgreSQL продолжает работать. Для разработки: **`npm run dev`**, адрес **http://localhost:5173**.

При первом запуске сервер применяет SQL-миграции и загружает четыре файла в пустую базу одной транзакцией. При последующих запусках читает PostgreSQL; seed-файлы уже не требуются. Локальный порт PostgreSQL — **5433**, чтобы не занимать стандартный порт установленного PostgreSQL. Параметры — `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_PORT`, `DATABASE_URL` в `.env`. Для собственной БД задайте `DATABASE_URL`; пользователь должен иметь право создавать схему и таблицы. При недоступной БД сервер завершает запуск с ошибкой.

## Подключение AI

Заполните локальный `.env` и перезапустите сервер:

```dotenv
LLM_BASE_URL=https://адрес-провайдера/v1
LLM_MODEL=имя-доступной-модели
LLM_API_KEY=ваш-ключ
LLM_TIMEOUT_MS=8000
```

`LLM_BASE_URL` — префикс перед `/chat/completions`; не включайте endpoint в переменную. Запрос содержит `model` и `messages`, без обязательного vendor-specific JSON mode. Модель должна вернуть JSON по промпту.

Без ключа, при таймауте или неправильном ответе работает **явно обозначенный резервный расчёт**. Он не выдаётся за AI. Модель получает проверенные кандидаты, факты о цели/навыках и агрегаты истории; имя и полный профиль не отправляются. Ключ доступен только серверу. Таймаут до 8 секунд, без повторов.

## Сценарий защиты

1. Сотрудник: роль, грейд, цель, текущие навыки и требования.
2. «Почему этот шаг»: цель/грейд, численный разрыв, история участия.
3. «Отметить выполнено»: изменяются навыки, прогресс, история и рекомендации.
4. HR → E0004: переход Data Analyst → Product Manager.
5. «Загрузить данные»: дополнительный JSON профилей и/или CSV истории.
6. HR: дефициты компетенций, отсутствие следующих шагов, участие.

Завершение — демонстрационная запись на дату среза, а не реальная регистрация. Автоматического повышения грейда нет.

## Импорт и сохранение

- Профили: `{"meta":{"as_of_date":"2026-10-01",...},"employees":[...]}` со схемой стартового набора. История — CSV с исходными колонками. Один или оба файла, до 12 МБ суммарно.
- Дата среза совпадает с каталогом. ID новых сотрудников не ограничены диапазоном E0001–E0200.
- Upsert по `employee_id` и `record_id`: совпадающая запись заменяется. Проверяются все ссылки после объединения; ошибка отменяет пакет целиком. Повторный импорт не дублирует записи.
- Завершения и импорт сохраняются в PostgreSQL транзакционно. Новый снимок публикуется в памяти после успешного `COMMIT`. Ошибка отменяет весь пакет; повторное завершение не начисляет прогресс заново.
- Уже заполненная БД не перезаписывается seed-файлами. Для чистого демо создайте отдельную пустую БД и укажите её в `DATABASE_URL`, сохранив прежнюю БД как резервную копию.
- Старый `data/runtime/state.json` автоматически не переносится и не изменяется. Файловое хранилище осталось внутренним вспомогательным механизмом тестов; сервер использует PostgreSQL.
- Схема: `careerquest.skills`, `role_profiles`, `employees`, `events`, `activity_history`, `dataset_metadata`. Основные поля, связи и ограничения — SQL; вложенные карты навыков и списки — JSONB. Миграции встроены в Go-бинарник из `backend/internal/store/migrations`.

## Архитектура и команда

```text
frontend/             вход, профиль, HR, API-клиент
backend/cmd/server/   запуск, конфигурация
backend/internal/
  model/              исходные схемы и API DTO
  auth/               серверные сессии
  httpapi/            маршруты и права
  store/              PostgreSQL, миграции, импорт JSON/CSV, валидация
  engine/             навыки, траектория, рейтинг, HR
  llm/                API модели и проверка выбора
contracts/            OpenAPI
scripts/              setup, demo, dev, проверки
data/                 локальные данные, вне Git
```

- №1: `codex/frontend`, интерфейс.
- №2: `codex/backend`, API/импорт/интеграция.
- №3: `codex/ai-engine`, алгоритм/AI.
- Общая рабочая версия: **`codex/mvp`**. Участники работают в отдельных клонах; персональные ветки создаются от общего рабочего коммита.

## Проверки

```powershell
npm run check
go -C backend vet ./...
```

Go-тесты, TypeScript и production-сборка. Тесты используют собственные минимальные фикстуры, без закрытого датасета и ключей. Linux CI дополнительно запускает race detector. [Результаты проверки](docs/VERIFICATION.md).

Для интеграционных тестов PostgreSQL выполните `npm run test:postgres`: скрипт использует `TEST_DATABASE_URL` или локальный `DATABASE_URL` из `.env`. Требуется право `CREATEDB`; каждый тест создаёт отдельную БД со случайным именем и удаляет только её. При обычном `go test` без `TEST_DATABASE_URL` эти тесты пропускаются; в CI PostgreSQL подключается автоматически. Проверяются перезапуск, идемпотентность, откат транзакции, повторный seed и защита от записи устаревшего снимка.

## Docker

После подготовки `.env` и `data/seed`, при работающем Docker Desktop:

```powershell
docker compose up --build
```

http://localhost:8080. Compose поднимает PostgreSQL и приложение, ожидая готовности БД. Seed монтируется read-only; PostgreSQL использует volume `postgres_data`. Контейнер приложения запускается непривилегированным пользователем. Локальное приложение и приложение в Compose используют одну БД; запускайте один экземпляр приложения. `docker compose down` сохраняет volume, а `docker compose down -v` удаляет данные БД.

## Границы MVP

Локальные демо-пароли показывают разделение прав, но не заменяют корпоративный SSO. По умолчанию сервер слушает только localhost. Один Go-процесс, без горизонтального масштабирования. Интерфейс русский, названия каталога английские. Нет реальной регистрации на мероприятия, мессенджеров, рейтингов и магазина наград.
