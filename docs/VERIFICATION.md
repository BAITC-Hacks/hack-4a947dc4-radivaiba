Браузерный и API-прогоны выполнены в отдельной БД `careerquest_qa_20260923` с отдельным контейнером на порту 8081. Основная БД содержит исходный набор без тестовых завершений и профилей. Синтетические фикстуры интеграционных тестов создаются в отдельных случайно названных БД; после тестов эти БД удаляются.

Проверка race detector настроена в Linux CI с PostgreSQL; локально race detector не запускался. Внешняя LLM не проверялась: ключ и модель не настроены. Приложение продолжает использовать прозрачный резервный расчёт.

## Повторить проверки

После `npm run setup -- --data-dir "<папка-набора>"`:

```powershell
docker compose up -d --wait postgres
npm run check
go -C backend vet ./...
npm run test:postgres
docker compose up -d --build careerquest
```

`test:postgres` берёт `TEST_DATABASE_URL` или локальный `DATABASE_URL` из `.env`. Пользователю тестовой БД нужно право `CREATEDB`. Скрипт создаёт и удаляет только собственные случайные БД. Без `TEST_DATABASE_URL` обычный `go test` пропускает PostgreSQL-тесты; CI передаёт эту переменную явно.

## Повторить API smoke

Создайте отдельную пустую QA-базу на тестовом PostgreSQL. В отдельном терминале задайте её URL (без вывода пароля в журнал), порт и демо-пароли:

```powershell
# DATABASE_URL должен указывать на отдельную QA-базу.
$env:PORT='8081'
$env:DEMO_EMPLOYEE_PASSWORD='qa-employee'
$env:DEMO_HR_PASSWORD='qa-hr'
$env:LLM_API_KEY=''
npm run demo

# Другой терминал
$env:QA_BASE_URL='http://127.0.0.1:8081'
$env:QA_EMPLOYEE_PASSWORD='qa-employee'
$env:QA_HR_PASSWORD='qa-hr'
node scripts/smoke.mjs
```

Smoke изменяет QA-базу: завершает активности и добавляет синтетический профиль. Для нового полного прогона используйте новую QA-базу. Исходные файлы, `.env` и данные PostgreSQL не входят в Git.
