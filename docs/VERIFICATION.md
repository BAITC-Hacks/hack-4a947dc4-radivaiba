## Финальная интеграция и рабочий запуск

23 сентября 2026 собран Docker image `workflow-20260923`. Внутри Linux-сборки прошли **все `go test ./...` и `go vet ./...`**, TypeScript и Vite production build. Отдельно повторно прошли 6 PostgreSQL-интеграционных тестов. Последний запуск `npm run check` на Windows был прерван системной Application Control при запуске `llm.test.exe`; ограничения Windows не отключались, тот же пакет и все остальные Go-тесты успешно выполнены внутри Docker.

Старое JSON-приложение остановлено перед финальным копированием. Snapshot ревизии 8 перенесён штатной командой в пустую PostgreSQL с dry-run, проверкой полей и транзакцией. Сохранены **200 сотрудников, 40 мероприятий с непустыми описаниями, 60 навыков, 2749 записей истории и 6 demo-завершений**. Создан 201 персональный аккаунт; старой истории EXP задним числом не начислялся. С учётом аккаунтов и настроек модулей рабочая ревизия — 10.

Приложение на `http://localhost:8080` теперь использует PostgreSQL и отдаёт `index-C8ixifLF.js` / `index-0pCcUC_P.css`. Health сообщает `storage=postgresql`, `build_version=workflow-20260923`. Проверены входы двух разных сотрудников и HR, свои профили, запрет HR-данных сотруднику и список 200 профилей. После `docker compose restart careerquest` те же проверки повторно прошли, ревизия сохранилась.

Резервная копия JSON: `data/backups/legacy-final-20260923/state.json`, SHA256 `bf058ee0af48a05c4f141c2f5207809f4bea5c54a087b7064e588d4ebe05de8d`. Старый volume `hack-4a947dc4-radivaiba_progress` и image `careerquest-legacy-backup:20260923` сохранены. Пароли находятся только в приватном Docker volume и игнорируемом `data/credentials/accounts.json`.

Браузерный сценарий выполнен на отдельной БД с двумя **вымышленными** сотрудниками: вход → реальный модуль этого тестового каталога → AI fallback → заявка → HR → подтверждение → автоматическое обновление дерева. До решения было 0 EXP, после — 30 EXP и рост готовности с 23,1% до 46,2%. Второй модуль прошёл возврат, исправленную версию и подтверждение; предыдущие материалы сохранились. Проверены RU/KZ/ENG, смена цели на другую роль без потери заявки/EXP, клавиатурное закрытие диалога, мобильный список и форма при ширине 390 px без горизонтального переполнения, а также desktop 1366 px. Скриншоты в `docs/images/` содержат только авторские вымышленные данные. Режим reduced-motion предусмотрен CSS; принудительная эмуляция системной настройки браузером отдельно не выполнялась.

Live-календарь проверен тестами: переход `Asia/Qyzylorda` из октября в ноябрь без перезапуска, позднее подтверждение, новый месячный лимит клуба и отмена в исходном месяце. В рабочей демонстрации календарь намеренно фиксирован на `2026-10-01`.

Реальная внешняя LLM в этом прогоне **не проверялась**: использовался резервный режим и unit-тесты адаптера.

**Локальная Linux race-проверка не завершена из-за окружения.** Установка C-компилятора через apk остановилась; образ Debian не загрузился из-за `tls: bad record MAC`. Финальная ограниченная попытка достигла 15 из 22 пакетов, но установка GCC превысила 120 секунд. Go race-тесты не начались, успешный результат не заявляется. В `.github/workflows/check.yml` остаётся Linux `go test -race ./...` с PostgreSQL; результат CI следует проверить отдельно. Повторные попытки отложены перед защитой.

## Повторить PostgreSQL-проверки

```powershell
docker compose up -d --wait postgres
npm run test:postgres
```

Скрипт использует `TEST_DATABASE_URL`, либо `DATABASE_URL` из `.env`. Нужны права `CREATEDB` на локальном тестовом PostgreSQL. Обычный `go test` без TEST_DATABASE_URL пропускает интеграционные тесты.

## Повторить API smoke

Создайте отдельную QA-базу, импортируйте/загрузите в неё данные, выполните provision с выводом в отдельный приватный JSON и запустите Go на порту 8081 с этой БД. Укажите отдельный EVIDENCE_DIR и пустой LLM_API_KEY. Только после этого:

```powershell
$env:QA_BASE_URL='http://127.0.0.1:8081'
$env:QA_CREDENTIALS_FILE='tmp/qa-accounts.json'
$env:QA_EMPLOYEE_LOGIN='E0004'
node scripts/smoke-workflow.mjs
```

Сценарий изменяет только указанную QA-базу: отправляет результат, проверяет HR-решения и отмену, импортирует синтетический профиль. Скрипт отказывается работать на порту 8080 и на удалённом адресе. Для полностью повторяемого прогона используйте новую отдельную QA-базу и новый каталог доказательств.
